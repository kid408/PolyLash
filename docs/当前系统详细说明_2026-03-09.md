# 当前系统详细说明（2026-03-09）

本文档基于当前代码实现整理，目标是让策划、程序、测试都能快速对齐「当前版本到底是怎么跑的」。

适用范围：
- 启动与存档流转
- 战斗主流程（波次、奖励、商店、下一波）
- 出怪导演预算系统
- 角色/技能（Q/E/F）、切换与队伍状态
- 招募/替换逻辑
- 羁绊、装备、仓库与经济
- 调试入口与排查路径

说明：
- 本文档描述的是“当前代码行为”，不是历史设计稿。
- 若文档与代码冲突，以代码为准。

## 1. 系统总览（当前版本）

核心玩法闭环是：
1. 开局选 1 名角色进入战斗。
2. 每波结束进入奖励结算（可出角色/属性/羁绊/其他）。
3. 满足商店波次时打开商店。
4. 商店关闭后进入下一波。
5. 通过角色切换 + Q/E/F 技能 + 羁绊/装备构建组合。

核心代码入口：
- 战斗主入口：`scenes/arena/arena_core.gd`
- 流程编排：`scenes/arena/battle_flow_controller.gd`
- 奖励流程：`scenes/arena/services/reward_flow_service.gd`
- 商店流程：`scenes/arena/services/shop_flow_service.gd`
- 奖励系统：`scenes/arena/wave_reward_system.gd`
- 出怪系统：`scenes/arena/spawner.gd`
- 角色主逻辑：`scenes/unit/players/player_base.gd`
- 技能管理：`scenes/skills/skill_manager.gd`
- 全局队伍状态：`autoloads/global.gd`
- 局内货币与经验：`autoloads/run_state_service.gd`
- 存档统一入口：`autoloads/save_facade.gd`

## 3. 主菜单 -> 选角 -> 战斗流程

### 3.1 主菜单行为（`main_menu_root.gd`）
- 新游戏：重置运行态与局内仓库，进入角色选择界面。
- 继续/读档：读取存档，恢复 `Global` 关键数据（角色、武器、队伍状态、羁绊、装备、仓库等），按 `game_state` 决定去选角或战斗。

### 3.2 选角行为（`selection_panel.gd`）
当前版本关键点：
- `max_selected_players = 1`（开局只允许选择 1 人）。
- 局外强化按钮、仓库按钮在选角界面已隐藏。
- 点击继续后：
  - 写入 `Global.selected_player_ids / selected_player_weapons`
  - `Global.init_player_states()`
  - 保存槽位初始存档
  - 进入 `res://scenes/arena/arena.tscn`

### 3.3 战斗初始化（`arena_core.gd`）
- 初始化奖励系统、流程控制器、商店信号、切换信号。
- `_init_player_from_selection()`：
  - 新开局（非战斗恢复）会执行 `Global.enter_wave_recruit_mode()`。
  - 这一步会把队伍改成“仅队长上场 + 其余进 reserve”。
- 初始化 HUD、羁绊显示、玩家信号。

## 4. 战斗主流程（波次结算）

当前波次结算链路：
1. `Spawner` 发 `wave_completed(wave_number)`。
2. `ArenaCore._on_wave_completed()` 执行：
   - 清理波末玩家技能效果
   - `Global.refill_squad_after_wave()`（当前小队回满血/能/护甲并清空冷却）
   - 记录 telemetry
3. 交给 `BattleFlowController.on_wave_completed()`：
   - 暂停刷怪
   - 先走奖励流程 `RewardFlowService`
   - 奖励结束后再决定是否开商店 `ShopFlowService`
4. 商店关闭后 `Spawner.resume_spawning()` 并 `start_next_wave()`。

## 5. 出怪系统（Spawner + 导演预算）

主文件：`scenes/arena/spawner.gd`

### 5.1 波次与计时器
- `SpawnTimer` 控制下一只怪生成间隔。
- `WaveTimer` 控制该波时长。
- `EliteSpawnTimer` 控制精英额外生成节奏。

### 5.2 配置来源（双轨）
- 旧配置：`wave_config.csv + wave_units_config.csv`
- 导演 v2：`wave_config_v2.csv + wave_units_config_v2.csv + enemy_config_v2.csv`

当前代码优先使用 v2（只要 v2 配置存在即 `_director_enabled = true`）。

### 5.3 导演预算核心
- 基础预算：`28 + 6*w + 0.8*w*w`
- 再乘 `budget_multiplier`
- Peak 波次（5/10/15/20）额外乘 `1.15`
- 还会计算一个按波时与间隔推导的 `timed_budget_floor`，预算不会低于它
- 每刷一只怪按 `cost` 累加 `_director_budget_spent`

### 5.4 结束波次条件
普通情况：
- `WaveTimer` 到时，停止刷怪并结算波次。

提前结束（可开关）：
- 受 `director_early_finish_enabled` 控制。
- 只有“预算耗尽 + spawn_timer停 + 场上无活怪”才提前结波。

当前默认配置 `director_early_finish_enabled = 0`，即默认不提前结波。

### 5.5 跳波键
- `Spawner._process()` 监听 `/`（主键盘和小键盘除号）触发 `go_to_next_wave()`。

### 5.6 波末清场
`clear_enemies(false)` + `_cleanup_wave_end_residuals()` 会清理：
- enemies
- items / coins
- projectiles / elite_projectiles
- player_skill_effects / enemy_effects

这保证波次切换时不会保留上一波残留对象。

## 6. 波次奖励系统（WaveRewardSystem）

主文件：`scenes/arena/wave_reward_system.gd`

### 6.1 奖励触发条件
`check_wave_reward(wave_number)` 返回 true 的条件：
- 当前波是招募波（`Global.should_offer_recruit_for_wave`）
- 或有掉落积分 `_pending_drop_points > 0`
- 或固定奖励波（常量 `[5,10,15]`）

### 6.2 掉落积分机制
- 普通怪掉落概率：`0.18`，积分 `1`
- 精英怪掉落概率：`0.55`，积分 `2`
- 每波积分上限：`6`

掉落积分影响奖励 tier（T1~T4）和金币奖励区间。

### 6.3 三选一生成规则
- 每次生成 3 个选项（`REWARD_OPTION_COUNT = 3`）。
- 类型池：`recruit / attribute / bond / other`
- 类型权重读 `game_config.csv`：
  - `reward_weight_recruit`（默认 55）
  - `reward_weight_attribute`（20）
  - `reward_weight_bond`（15）
  - `reward_weight_other`（10）

同一轮会尽量避免重复类型，不够时允许重复，确保凑齐 3 项。

### 6.4 招募与替换
未满员：
- 生成 `type=recruit`
- 花费 `recruit_cost_add_member`（默认 260）

满员：
- 生成 `type=recruit_replace`
- 卡片只占一个奖励格子
- 点击后弹“替换目标选择层”
- 队长不可被替换（`Global.replace_player` 明确拦截）

当前费用：
- `recruit_cost_add_member = 260`
- `recruit_cost_replace_member = 260`

### 6.5 奖励类型明细
- `recruit / recruit_replace`：招募或替换招募
- `attribute_boost`：加最大生命/最大能量/能量回复/移速
- `artifact`：给护符（Emblem）
- `equipment`：给仓库道具
- `gold`：直接加 run_gold

### 6.6 奖励面板与二次交互
`WaveRewardPanel` 支持：
- 三卡展示
- 招募替换二次弹层（选择替换目标）
- 波末嵌入角色强化面板按钮（`UpgradeButton`）

## 7. 商店系统（波间商店）

相关文件：
- `scenes/arena/services/shop_flow_service.gd`
- `scenes/ui/shop_panel/shop_panel.gd`
- `autoloads/shop_manager.gd`
- `autoloads/shop_domain_service.gd`
- `autoloads/shop_attribute_manager.gd`

### 7.1 商店开关时机
- `SHOP_INTERVAL_WAVES = 2`
- 即默认每 2 波出现一次商店（`wave_number % 2 == 0`）

### 7.2 商店物品生成
`ShopManager.generate_shop_items(3)` 当前每次生成 3 张卡：
- 25% 概率徽章（emblem）
- 否则装备（equipment）
- 极端兜底走旧 consumable 池

### 7.3 事务与回滚
购买/刷新都通过 `ShopDomainService`：
- 扣钱成功后执行回调
- 回调失败会自动退款

### 7.4 价格与刷新
- 刷新价格常量：`REROLL_COST = 20`
- 商店关闭时会触发自动存档（trigger=`shop_closed`）

## 8. 队伍、招募与切换（Global）

主文件：`autoloads/global.gd`

### 8.1 队伍状态结构
- `selected_player_ids`：当前上阵队伍（上限 3）
- `reserve_player_ids`：后备招募池
- `leader_player_id`：队长（不可替换）
- `player_states`：每个角色独立血量/能量/护甲/冷却快照

### 8.2 波次招募模式
`enter_wave_recruit_mode()` 会：
- 只保留首位角色上场
- 其余进入 reserve
- 后续通过奖励波招募扩编到 2 人 / 3 人

### 8.3 招募波触发
`should_offer_recruit_for_wave(wave)` 使用配置：
- `recruit_first_wave`（默认 3）
- `recruit_wave_interval`（默认 2）

默认就是：3、5、7、9... 波都可触发招募（前提 reserve 非空）。

### 8.4 替换规则
`replace_player(out, in)` 关键限制：
- `out` 必须在 active 队伍
- `out` 不能是 `leader_player_id`
- `in` 必须来自 reserve

若替换的是当前出战角色，会立即发 `on_player_switch_requested` 切角色实例。

### 8.5 切换冷却与切换协同
- 基础切换冷却：`0.2s`（可被羁绊减免）
- 切换后有短窗口，首个技能可吃到协同加成（在 `SkillManager` 里消耗）

### 8.6 波次结束回满
`refill_squad_after_wave()`：
- active 队伍所有角色：血/能/护甲回满
- 技能冷却清空
- 同步当前激活角色实例与 HUD

## 9. 角色与技能系统（Q/E/F）

相关文件：
- `scenes/unit/players/player_base.gd`
- `scenes/skills/skill_manager.gd`
- 各角色技能脚本：`scenes/skills/players/*.gd`

### 9.1 输入分发（当前实现）
`PlayerBase._handle_input(delta)`：
- `skill_e`：即时 `execute_skill("e")`
- `skill_q` 按住：`charge_skill("q", delta)`
- `skill_q` 松开：`release_skill("q")`
- `click_left`：`execute_skill("lmb")`
- `skill_f`：调用 `ultimate_skill.try_activate()`

### 9.2 SkillManager 装载机制
- 按 `player_skill_bindings.csv` 给 `q/e/lmb/rmb` 装脚本
- 脚本路径规范：`res://scenes/skills/players/{skill_id}.gd`
- 参数来自 `skill_params_wide.csv`
- 支持导出/导入冷却快照（角色切换时保留冷却进度）

### 9.3 角色切换时的技能效果策略
`ArenaCore._on_player_switch_requested()` 当前策略：
- 默认不清理旧角色技能效果（效果可持续）
- 新角色生成后继续战斗

波次结束时会统一清理（见第 11 节）。

## 10. 羁绊系统（Bond）

主文件：`autoloads/bond_manager.gd`

### 10.1 标签来源（四源）
1. 角色自带：`origin_tag/mastery_tag/tactic_tag`
2. 装备提供：`bond_grant`
3. 护符提供：Emblem tags
4. 临时标签：战斗中临时加成

### 10.2 激活规则
- 按 `bond_config_v3.csv` 的阈值计算等级。
- 3 级激活有额外门槛：必须至少有“运行时来源”（装备/护符/临时标签），纯角色人数不能直上 3 级。

### 10.3 对战斗影响
- `apply_stat_modifiers()` 对玩家运行时属性做二次修改。
- 还支持 mechanic 类效果（如切换冷却减免、镜像绘制、共享属性等）。

## 11. 装备与仓库系统（局内化）

### 11.1 仓库（WarehouseManager）
- 当前是“局内仓库模式”：开局空仓库。
- 道具主要来源：奖励、商店。
- 存档恢复通过 `SaveFacade`，不再独立写旧仓库文件。

### 11.2 装备（EquipmentManager）
- 记录 `player_id -> item_type`
- 支持穿戴、替换、卸下
- 可通过 `bond_grant` 影响羁绊标签

## 12. 经济与进度存档

### 12.1 货币语义（DataManager + RunStateService）
- `run_gold`：局内金币（商店/招募消耗）
- `soul_shard`：局外碎片（长线成长）

`RunStateService` 是局内 gold/xp 的统一入口，避免各处直接改 DataManager。

### 12.2 波间自动存档
关键触发：
- 角色切换（`character_switch`）
- 商店关闭（`shop_closed`）
- 返回主菜单/退出

统一由 `BattleFlowController -> RunSaveService -> SaveFacade` 执行。

### 12.3 失败结算后的槽位处理
`ArenaCore._save_progress_on_run_failed()`：
- 存档状态切回 `character_selection`
- `current_wave` 重置为 1（并记录 `last_failed_wave`）
- 仅保留开局队长到选角缓存

## 13. 波次结束/结束战局清理策略

### 13.1 波次结束时
`ArenaCore._on_wave_completed()` 会执行：
- `_cleanup_wave_end_player_effects()`
- `_cleanup_wave_end_global_skill_effects()`
- `Spawner.clear_enemies(false)` 触发场景残留清理
- `Global.refill_squad_after_wave()`

### 13.2 战局结束/返回菜单时
`prepare_run_exit_cleanup()`：
- 重置 `Engine.time_scale = 1.0`
- 清理全局 pause source
- 清理玩家技能规划态/大招态/状态组件
- 清理投射物与技能残留节点

## 17. 常见问题排查路径

1. 波次结束后没进奖励/商店  
查看：`arena_core.gd::_on_wave_completed` -> `battle_flow_controller.gd` -> `reward_flow_service.gd` -> `shop_flow_service.gd`

2. 招募替换不生效/队长被替换  
查看：`wave_reward_system.gd::_apply_recruit_replace_reward` 与 `global.gd::replace_player`

3. 商店扣钱了但道具没生效  
查看：`shop_manager.gd::purchase_item` -> `shop_domain_service.gd::try_purchase` -> `purchase_effect_pipeline.gd`

4. 波次时间还没到就结束  
查看：`spawner.gd::_try_finish_wave_when_budget_drained` 与 `game_config.csv` 的 `director_early_finish_enabled`

5. 切角色后技能冷却异常  
查看：`player_base.gd::queue_restore_skill_cooldowns` 与 `skill_manager.gd::import_cooldown_state`

6. 波次结束后仍有技能残留  
查看：`arena_core.gd::_cleanup_wave_end_player_effects`、`_cleanup_wave_end_global_skill_effects`、`spawner.gd::_cleanup_wave_end_residuals`
