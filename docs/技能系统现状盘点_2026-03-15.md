# 技能系统现状盘点（2026-03-15）

## 1. 结论摘要

截至 2026-03-15，技能系统代码主链已经基本完成从“编号原型 / 旧兼容岛”向“角色语义脚本 + 统一 Q/E/F 基类 + 语义桥接”的收口。

- `Q` 主链使用 `skill_<role>_q.gd`，复杂画线实现保留在 runtime 文件中，但不再直接挂主配表。
- `E` 主链使用 `skill_<role>_e.gd`，32 个角色脚本全部继承 `SkillEBase`。
- `F` 主链使用 `f_roles/skill_<role>_f.gd`，32 个角色 wrapper 全部继承 `SkillFBase`。
- `ult_config.csv` 已完成 `f_mode_id -> f_role_id` 语义化，调试面板与运行时快照也统一输出 `f_role_id`。
- `skill_eXX.gd` / `skill_fXX.gd` / `*_proto.gd` / `*_refactored.gd` / `skill_ultimate_qef_v3.gd` 已不再保留为仓库主链债务。
- 自动化验收闭环已经具备，当前剩余工作不再是命名和迁移，而是主观实机玩法验收、逐角色数值回归，以及多角色录制/回放样本扩充。

## 2. 主链入口盘点

### 2.1 输入与技能槽

- 输入主入口：`scenes/unit/players/player_base.gd`
- Q/E/LMB/RMB 槽位调度：`scenes/skills/skill_manager.gd`
- F 加载入口：`player_base.gd::_get_ultimate_script_for_player`
- 输入覆写现状：仅 `player_base.gd` 保留 `_handle_input()`，角色脚本侧重复输入逻辑已收敛。

当前职责边界：

- `PlayerBase` 负责输入、角色切换、Q 对 F 的事件转发、F 脚本装配。
- `SkillManager` 负责 Q/E/LMB/RMB 的实例化、冷却、消耗、快照。
- `SkillEffectManager` 继续承担效果结算，不再负责技能语义拼装。

### 2.2 语义桥接层

已落地的基础设施：

- `debug_switcher.gd` 已能显示 `Q` / `F` 上下文、留场资产数与反馈日志字段。

### 2.3 配表与调试入口

- 主绑定：`config/player/player_skill_bindings.csv`

## 5. 已落地的关键面

### 5.1 Q 抽象层

- `Q` 已由 `SkillQBase` 统一承接上下文发布、留场资产注册与对 F 的路径事件通知。
- 复杂 Q 角色通过可读 wrapper 挂接 runtime，实现文件仍保留在 `scenes/skills/players/` 作为内部实现，而非主绑定入口。

当前保留的复杂 Q runtime：

- `skill_saw_path.gd`（butcher）
- `skill_web_weave.gd`（weaver）
- `skill_lurewarden_loop.gd`（lurewarden）
- `skill_fire_path.gd`（pyro）
- `skill_mine_path.gd`（sapper）
- `skill_wind_path.gd`（wind）

### 5.2 E 抽象层

- `E` 已由 `SkillEBase` 统一承接最近 Q 上下文读取与 E 上下文发布。
- 32 个角色 E 脚本都已进入 `skill_<role>_e.gd` 主命名路径。
- 核心 6 角色仍保留手写 E 窗口资产；其余角色已由 `SkillEBase` 自动补发标准 E 上下文，供 F、调试层和运行时快照读取。

核心 E 窗口资产：

- butcher -> `butcher_hook_window`
- weaver -> `weaver_recall_window`
- lurewarden -> `lurewarden_pack_window`
- pyro -> `pyro_blaze_step`
- glacier -> `glacier_shatter_window`
- quartermaster -> `quartermaster_resupply`

### 5.3 F 抽象层

- `F` 已由 `SkillFBase` 统一承接开窗、tick、Q 路径响应、F 上下文发布与运行时剖面。
- 32 个 `f_roles/skill_<role>_f.gd` wrapper 全部继承 `SkillFBase`，并改用 `_resolve_f_role_id()` 输出角色语义 ID。
- F 窗口优先通过 `SkillContextBridge.get_recent_e_asset()` 读取 E 资产，旧 `player meta` 仅保留为少量兜底兼容。

### 5.4 配表与调试

- `player_skill_bindings.csv`、`skill_params_wide*.csv` 与 wrapper 脚本名已对齐为同一套语义技能 ID。
- `ult_config.csv`、`ConfigRepository`、`SkillUltimate`、`debug_switcher.gd` 全部改用 `f_role_id`。
- 反馈 CSV 已追加 `skill_f`、`ult_id`、`f_role_id`、`desc_f` 字段，技能关注维度已切到 Q/E/F 语义项。

## 7. 现状判断

### 已经成立

- 32 个角色的 Q/E/F 文件命名、主绑定与基类继承体系已经统一。
- `f_mode_id` / `mode_id` 兼容命名已经从运行时代码主链中清退，统一收口到 `f_role_id`。
- 角色输入层的重复 `_handle_input()` 逻辑已收敛回 `player_base.gd`。
- 调试面板、反馈日志与运行时快照已经能读取新的语义技能字段。
- 已完成 6 个核心角色（`butcher`、`weaver`、`lurewarden`、`pyro`、`glacier`、`quartermaster`）的 CLI 自动验收，覆盖 `Q 开线 / Q 闭合 / E / F`，`qef_acceptance_summary.json` 在 `2026-03-15 12:13:42` 记录为 `passed=true`。
- 已完成至少 7 个角色的 `录制 -> 回放 -> 反馈` 自动闭环样本：`butcher`，以及新增 `wind / lurewarden / quartermaster / singularist / banner / pyro`，反馈 CSV 已实际写入 `skill_f`、`ult_id`、`f_role_id`、`desc_f`。

### 尚未完成

- 尚未完成全部 32 个角色的主观实机玩法验收，尤其是 `Q 开线 / Q 闭合 / E 二次操作 / F 10 秒窗口` 的真实手感与高光密度仍需人工确认。
- 录制 / 回放 / 评价链路虽已完成至少 7 个角色自动闭环样本，但多角色全覆盖与主观标签积累仍未完成。
- 尚未做完整的逐角色数值回归，因此当前结论仍以“结构与自动化验收完成”而非“玩法与平衡验收完成”为准。
- 尝试把 `headless` `QEF` 自动验收直接扩到 32 个角色时，部分 draw-Q 角色会出现“输入已执行但闭合上下文未被 CLI 鼠标路径稳定触发”的测试偏差；这说明全量自动化还要继续补，而不是说明这些角色仍停留在旧技能。
