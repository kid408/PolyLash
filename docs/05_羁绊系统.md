# 羁绊系统 (BondManager)

## 系统概述

羁绊系统是 PolyLash 的核心数值系统，通过收集羁绊标签来激活不同等级的羁绊效果，提供属性加成和特殊机制。

**核心特点**:
- 三源标签统计（角色、装备、徽章）
- 多等级激活机制（Lv.1-3）
- 属性修改器（stat_mod）
- 特殊机制（mechanic）
- 实时重算和信号通知
- 临时标签系统（大招/技能）
- 变身过载模式（F键大招）

### 羁绊类型（3大类）

#### 1. 起源羁绊（Origin）

| alchemist | 后勤 | 2 | 3 | 5 | 拾取范围提升，线条产出金币 |

代表角色的职业技能，影响画线技能效果。

```gdscript
var item_data = EquipmentManager.get_equipped_item_data(player_id)
```

## 羁绊激活机制

### 等级激活规则
1. 统计当前所有来源的标签数量
2. 检查每个羁绊的等级需求
3. 激活满足条件的最高等级
4. 收集该等级及以下的所有效果

**示例**:
```gdscript
# 当前标签: inkborn = 5
# 羁绊配置:
#   Lv.1: 需要 2 个标签
#   Lv.2: 需要 4 个标签
#   Lv.3: 需要 6 个标签
# 结果: 激活 Lv.2，应用 Lv.1 + Lv.2 的效果
```

### 变身过载模式
当启用变身过载模式时（F键大招）：
- 只要有1个标签就激活最高等级
- 用于临时强化羁绊效果

```gdscript
BondManager.set_overdrive_mode(true)
# 现在 inkborn = 1 也会激活 Lv.3
```

## 效果类型

### 1. 属性修改器 (stat_mod)

#### 固定值属性
直接加到属性上：
```csv
effect_type,effect_param,effect_value,description
stat_mod,crit_chance,0.05,暴击率 +5%
stat_mod,max_health,50,最大生命 +50
stat_mod,armor,1,护甲 +1
```

#### 百分比属性（_pct 后缀）
基于当前值的乘法加成：
```csv
effect_type,effect_param,effect_value,description
stat_mod,energy_regen_pct,0.20,能量恢复 +20%
stat_mod,max_health_pct,0.15,最大生命 +15%
stat_mod,speed_pct,0.10,移动速度 +10%
```

**计算公式**:
```
固定值: Final = Base + Value
百分比: Final = Base * (1.0 + Value)
```

#### 支持的属性列表
| 属性名 | 说明 | 类型 |
|--------|------|------|
| crit_chance | 暴击率 | 固定值 |
| crit_damage | 暴击伤害 | 固定值 |
| energy_regen | 能量恢复 | 固定值/百分比 |
| max_health | 最大生命 | 固定值/百分比 |
| speed | 移动速度 | 固定值/百分比 |
| armor | 护甲 | 固定值 |
| cooldown_reduction | 冷却缩减 | 固定值 |
| gold_gain | 金币获取 | 固定值 |
| exp_gain | 经验获取 | 固定值 |
| dodge_chance | 闪避率 | 固定值 |
| health_regen | 生命恢复 | 固定值 |
| projectile_speed | 弹道速度 | 固定值 |
| heal_power | 治疗强度 | 固定值 |
| damage_taken_reduction | 伤害减免 | 固定值 |
| pickup_range | 拾取范围 | 固定值/百分比 |

### 2. 特殊机制 (mechanic)

机制效果不直接修改属性，而是提供特殊功能。

**查询方式**:
```gdscript
# 检查是否激活
if BondManager.has_mechanic("energy_overflow"):
    # 执行能量溢出逻辑
    pass

# 获取机制数值
var value = BondManager.get_mechanic_value("switch_cd_reduce")
```

#### 已实现的机制列表

| 机制名 | 说明 | 数值含义 |
|--------|------|----------|
| energy_overflow | 能量溢出转化护盾 | 转化比例 |
| switch_cd_reduce | 切换冷却减少 | 减少百分比 |
| stat_share | 属性共享（P4-3） | 共享比例 |
| dash_reset_on_kill | 击杀重置冲刺 | 1=启用 |
| projectile_pierce | 弹道穿透 | 穿透次数 |
| aoe_expand | AOE范围扩大 | 扩大百分比 |

## 核心API

### 重新计算羁绊
```gdscript
func recalculate_active_bonds(team_player_ids: Array, equipped_relics: Array = []) -> void
```

**调用时机**:
- 游戏开始时
- 角色切换时
- 装备变更时
- 徽章添加/移除时

**示例**:
```gdscript
var team_ids = ["player_herder", "player_pyro", "player_glacier"]
BondManager.recalculate_active_bonds(team_ids)
```

### 查询羁绊状态
```gdscript
# 获取羁绊激活等级
var level = BondManager.get_active_bond_level("inkborn")  # 返回 0-3

# 获取羁绊当前标签数量
var count = BondManager.get_bond_current_count("inkborn")

# 检查羁绊是否激活
if BondManager.is_bond_active("inkborn"):
    print("墨生世家已激活")

# 获取所有激活的羁绊
var active_bonds = BondManager.get_all_active_bonds()
```

### 应用属性修改
```gdscript
func apply_stat_modifiers(player_stats: Dictionary) -> Dictionary
```

**使用示例**:
```gdscript
# 在 PlayerBase 中应用羁绊加成
var base_stats = {
    "max_health": 100,
    "energy_regen": 0.5,
    "speed": 300
}

var modified_stats = BondManager.apply_stat_modifiers(base_stats)
# 返回应用羁绊加成后的属性
```

### 临时标签管理
```gdscript
# 添加临时标签（大招激活时）
BondManager.add_temp_tag("inkborn")
```

## 特殊功能

### P4-3: 属性共享（指挥型 Lv.1）
后台角色的基础属性按比例共享给当前角色。

**配置**:
```csv
bond_id,level,effect_type,effect_param,effect_value
commander,1,mechanic,stat_share,0.20
```

**效果**:
- 后台角色的攻击力、生命、速度 * 20% 加到当前角色
- 只计算基础值，不包括羁绊加成

**实现**:
```gdscript
func _apply_stat_share(stats: Dictionary) -> void:
    var share_ratio = get_mechanic_value("stat_share")
    var bench_characters = _get_bench_characters()
    
    for char_id in bench_characters:
        var char_config = ConfigManager.get_player_config(char_id)
        var base_damage = float(char_config.get("damage", 0))
        stats["damage"] += base_damage * share_ratio
```

### P4-1: 切换冷却减少（突击型 Lv.1）
减少角色切换的冷却时间。

**配置**:
```csv
bond_id,level,effect_type,effect_param,effect_value
vanguard,1,mechanic,switch_cd_reduce,0.25
```

**效果**:
- 基础切换冷却: 10秒
- 激活后: 10 * (1 - 0.25) = 7.5秒

## 常见问题

### Q1: 为什么羁绊没有激活？
**检查清单**:
1. 标签数量是否达到要求
2. 配置文件是否正确加载
3. 是否调用了 `recalculate_active_bonds()`
4. 检查标签来源: `get_tag_sources(bond_id)`

### Q2: 属性加成没有生效？
**检查清单**:
1. 是否调用了 `apply_stat_modifiers()`
2. 属性名是否正确（注意 _pct 后缀）
3. 是否监听了 `stat_modifiers_changed` 信号
4. 检查 PlayerBase 的属性应用逻辑

### Q3: 如何添加新的羁绊？
**步骤**:
1. 在 `bond_config.csv` 中添加配置
2. 在角色配置中添加对应标签
3. 重启游戏加载配置
4. 测试激活和效果

### Q4: 如何添加新的机制效果？
**步骤**:
1. 在 `bond_config.csv` 中添加 mechanic 类型效果
2. 在需要的地方使用 `has_mechanic()` 检查
3. 使用 `get_mechanic_value()` 获取数值
4. 实现具体的机制逻辑

## 最佳实践

### 1. 羁绊设计原则
- Lv.1: 基础加成（10-20%）
- Lv.2: 中等加成（30-50%）
- Lv.3: 强力加成或特殊机制

### 2. 标签分配建议
- 每个角色3个标签（起源+精通+战术）
- 装备提供1-2个标签
- 徽章提供1个标签

### 3. 性能优化
- 只在必要时调用 `recalculate_active_bonds()`
- 使用信号通知而不是轮询
- 缓存计算结果

### 4. 调试技巧
- 使用 `print_active_bonds()` 查看状态
- 使用 `get_tag_sources()` 追踪标签来源
- 监听 `bond_level_changed` 信号

## 实现细节

### 羁绊计算流程

```
1. 清空当前数据
   ├─ current_bond_counts.clear()
   ├─ tag_sources.clear()
   └─ active_bonds.clear()

2. 统计三源标签
   ├─ _count_character_tags()    # 来源1: 角色自带
   ├─ _count_equipment_tags()    # 来源2: 装备 bond_grant
   └─ _count_emblem_tags()       # 来源3: 全局徽章

3. 添加临时标签
   └─ _add_temp_tags()           # 技能/大招临时标签

4. 检查激活状态
   ├─ _get_activated_level()     # 计算激活等级
   └─ _activate_bond()           # 收集效果

5. 检测等级变化
   └─ _detect_level_changes()    # 发出信号

6. 发出信号
   ├─ bonds_recalculated.emit()
   └─ stat_modifiers_changed.emit()
```

### 属性应用流程

```
1. 获取基础属性
   └─ player_stats = {...}

2. 应用羁绊加成
   └─ BondManager.apply_stat_modifiers(player_stats)
      ├─ 遍历所有激活羁绊的 stat_mod 效果
      ├─ _apply_stat_modifier() 应用单个属性
      └─ _apply_stat_share() 应用属性共享（P4-3）

3. 返回修改后的属性
   └─ modified_stats
```

### 机制效果查询流程

```
1. 检查机制是否激活
   └─ BondManager.has_mechanic("energy_overflow")

2. 获取机制数值
   └─ BondManager.get_mechanic_value("switch_cd_reduce")

3. 执行机制逻辑
   └─ 在具体系统中实现（如技能系统、切换系统）
```
