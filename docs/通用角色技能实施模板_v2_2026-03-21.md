# 通用角色技能实施模板 v2（2026-03-21）

## 1. 这版模板比旧骨架多补了什么

基于 [屠夫技能规则示例.txt](/D:/wanglei/PolyLash/docs/archive/legacy-qef/屠夫技能规则示例.txt) 抽出来的旧骨架，已经有很强的“可实施感”，但对当前项目来说还不够完整。

如果只保留旧骨架：

- 容易把角色写成“技能会做什么”，但写不出“为什么这个角色和别的角色不一样”
- 容易写出单技能说明，但写不出三角色切换时的交接价值
- 容易写出单次爽点，但写不出 `F` 的 10 秒回场收账逻辑
- 容易写出机制，但写不出“如何验收角色没有同构、没有空心、没有越位”

因此这版模板额外补了 8 个关键模块：

- `角色边界定义`
- `核心动作词 / 核心名词`
- `战场目标变化`
- `地形适配`
- `精英 / Boss 替代收益`
- `新手线 / 高手线`
- `空放与失败保底`
- `反同构与系统自检`

这 8 块不是装饰项，而是为了让角色文档真正变成“可设计、可讨论、可验收”的实施稿。

## 2. 写作原则

### 2.1 不允许空话

角色实施稿里禁止直接用下面这些句子充当设计：

- “造成持续伤害”
- “控制敌人”
- “提高输出”
- “增强生存”
- “形成区域压制”
- “制造爽感”

这些都不算实施语言。

必须替换成可被看见、可被操作、可被验收的结构语言，例如：

- 把怪沿线送向锚点
- 让怪一直走错门
- 把怪勒成一团
- 把错误追击改成露背
- 把口袋越收越紧
- 把补给线推成进攻线
- 把安全面推成反打面

### 2.2 角色必须有核心动作词

每个角色都必须先定一个 `核心动作词`，再写技能。

动作词建议只取 `1` 个主词 + `1` 个副词，例如：

- `拴住 + 处刑`
- `走错 + 判罚`
- `勒团 + 回收`
- `追错 + 露背`
- `加工 + 升拍`
- `补给 + 刷新`
- `救治 + 反打`
- `入袋 + 收紧`

如果一个角色写完以后，动作词还能轻易换成别的角色，说明同构风险很高。

### 2.3 角色必须有核心名词

每个角色都必须有 2 到 4 个可反复出现的签名名词，用来固定视觉和心智。

例如：

- 锚点 / 处刑口
- 合法口 / 死门
- 网囊 / 囊口
- 诱饵桩 / 假路径
- 热槽 / 锻位
- 补给箱 / 回路
- 医区 / 前插站
- 夹口 / 猎袋

没有签名名词的角色，后面很容易写成空泛的机制堆砌。

## 14. 反同构检查

在进入数值前，必须强制回答下面 6 条：

1. 去掉元素名后，这个角色还剩什么行为结构？
2. 如果把这个角色描述里的关键词替换给另一个角色，会不会也说得通？
3. 它的 `Q` 做局方式是不是一眼可认？
4. 它的 `Q 闭合` 兑现方式是不是独占的？
5. 它的 `F` 回场收账路径是不是别的角色不能简单替代？
6. 它为后手留下的价值，是否和近邻角色明显不同？

如果有 `2` 条以上答不稳，就不能进入细化阶段。

---

## 15. 系统自检

在进入数值前，必须再做一次系统自检：

- 是否让 `E` 抢走了 `Q` 的主玩法位置
- 是否让 `dash` 越位成主输出
- 是否让 `F` 脱离前面的做局独立成立
- 是否还能落进既定资源原型
- 是否在 `日常 / 高压 / 高光` 三套模板里站得住
- 是否真的逼玩家回到自己做好的场里收账

如果角色很帅，但过不了系统自检，优先回调结构，而不是硬补特权。

---

## 16. 最终结论

最后必须用下面 3 句收束：

- 这个角色不该再被描述成什么
- 这个角色现在应该被描述成什么
- 用 `4 - 6` 个动作词收束它的玩法

例如：

- 不该再被描述成“一个会放控制圈的近战”
- 应该被描述成“把怪拴去处刑口的收账角色”
- 动作词：`投锚、拖行、压缩、收口、处刑`

## 4. 我认为这套模板相对旧版最重要的升级

如果只看最关键的升级，我认为有 5 条：

- 从“写技能效果”升级为“先写角色边界”
- 从“写机制”升级为“写玩家想把战场改成什么样”
- 从“写单技能”升级为“写切人后留下什么价值”
- 从“写爽点”升级为“写 `F` 如何逼玩家回场收账”
- 从“写完就算”升级为“必须过反同构检查和系统自检”

## 5. 使用建议

后续所有样板角色，都统一按下面顺序写：

1. 角色总述
2. 战场目标
3. 角色边界
4. `Q 非闭合`
5. `Q 闭合`
6. `E 单按`
7. `Q 非闭合 -> E`
8. `Q 闭合 -> E`
9. `E -> dash`
10. `F`
11. `精英 / Boss 替代收益`
12. `切人交接`
13. `操作节奏`
14. `反同构检查`
15. `系统自检`
16. `最终结论`

这就是我认为当前项目最适合的通用角色技能实施模板。
