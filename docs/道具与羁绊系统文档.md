# 道具与羁绊系统文档

> 项目: PolyLash  
> 更新日期: 2026-02-16

---

## 一、系统概述

PolyLash 的道具与羁绊系统是游戏核心策略层的基础。玩家通过选择角色组合、装备道具、收集徽章来激活羁绊效果，从而获得属性加成和特殊机制。

### 1.1 系统架构总览

```
┌─────────────────────────────────────────────────────────┐
│                     配置层 (CSV)                         │
│  bond_config.csv  item_config.csv  emblem_config.csv    │
│  item_effect_config.csv  shop_item_config.csv           │
└──────────────────────┬──────────────────────────────────┘
                       │ 启动时加载
┌──────────────────────▼──────────────────────────────────┐
│                  ConfigManager (Autoload)                │
│  统一加载/缓存所有 CSV，提供 get_xxx_config() 接口       │
└──────────────────────┬──────────────────────────────────┘
                       │
       ┌───────────────┼───────────────┐
       ▼               ▼               ▼
┌─────────────┐ ┌─────────────┐ ┌─────────────┐
│ BondManager │ │EquipmentMgr│ │ EmblemMgr   │
│ 羁绊核心逻辑│ │ 角色装备管理│ │ 徽章/遗物   │
└──────┬──────┘ └──────┬──────┘ └──────┬──────┘
       │               │               │
       ▼               ▼               ▼
┌─────────────────────────────────────────────────────────┐
│              WarehouseManager (仓库 48 格)               │
│              ModifierManager (标签修改器)                 │
│              ShopManager (波次间商店)                     │
└─────────────────────────────────────────────────────────┘
```

## 二、羁绊系统 (Bond System)

### 2.1 核心概念

每个角色携带 3 个羁绊标签：`origin_tag`（身世）、`mastery_tag`（职能）、`tactic_tag`（战术）。当队伍中同一标签的数量达到阈值时，对应羁绊被激活。

标签来源有三种：
1. 角色自带标签（player_config.csv）
2. 装备的 Tier 3 圣物提供的 `bond_grant` 标签
3. 全局徽章（EmblemManager）提供的标签

### 2.2 羁绊分类

| 类型 | 标签 | 显示名 | 颜色 |
|------|------|--------|------|
| origin | inkborn | 魔导 | 森林绿 |
| origin | colossus | 重装 | 森林绿 |
| origin | nomad | 游侠 | 森林绿 |
| origin | alchemist | 后勤 | 森林绿 |
| mastery | blaster | 爆破师 | 深红 |
| mastery | architect | 筑墙者 | 深红 |
| mastery | hexer | 咒术师 | 深红 |
| mastery | geometrist | 几何学家 | 深红 |
| tactic | assist | 支援型 | 矢车菊蓝 |
| tactic | vanguard | 突击型 | 矢车菊蓝 |
| tactic | commander | 指挥型 | 矢车菊蓝 |

### 2.3 激活阈值

Origin/Mastery 羁绊有 3 级，Tactic 羁绊有 2 级：

| 等级 | Origin/Mastery 需求 | Tactic 需求 |
|------|---------------------|-------------|
| Lv.1 | 2 | 2 |
| Lv.2 | 3 | 4 |
| Lv.3 | 5 | — |

### 2.4 效果类型

- `stat_mod`：属性修改，通过 `BondManager.apply_stat_modifiers()` 自动应用到玩家属性
- `mechanic`：机制效果，需要在技能/战斗代码中主动查询

### 2.5 核心管理器: BondManager

文件路径: `autoloads/bond_manager.gd`

#### 主要属性

| 属性 | 类型 | 说明 |
|------|------|------|
| `bond_configs` | Dictionary | 羁绊配置 `{bond_id: {bond_type, display_name, levels[]}}` |
| `active_bonds` | Dictionary | 当前激活的羁绊 `{bond_id: {level, effects[], bond_type}}` |
| `current_bond_counts` | Dictionary | 当前标签统计 `{bond_id: count}` |
| `tag_sources` | Dictionary | 标签来源追踪 `{tag: {character, equipment, emblem}}` |
| `temp_bonus_tags` | Dictionary | 临时标签（大招/技能） |

#### 主要信号

| 信号 | 参数 | 触发时机 |
|------|------|----------|
| `bonds_recalculated` | `active_bonds: Dictionary` | 羁绊重新计算完成 |
| `stat_modifiers_changed` | 无 | 属性修改器变化 |
| `bond_level_changed` | `bond_id, old_level, new_level` | 羁绊等级变化 |

#### 核心函数

```gdscript
# 重新计算所有羁绊（队伍变化时调用）
func recalculate_active_bonds(team_player_ids: Array, equipped_relics: Array = []) -> void

# 应用 stat_mod 效果到玩家属性
func apply_stat_modifiers(player_stats: Dictionary) -> Dictionary

# 查询机制效果
func has_mechanic(mechanic_name: String) -> bool
func get_mechanic_value(mechanic_name: String) -> float

# 获取羁绊信息
func get_active_bond_level(bond_id: String) -> int
func get_bond_current_count(bond_id: String) -> int
func is_bond_active(bond_id: String) -> bool
func get_bond_display_name(bond_id: String) -> String
func get_bond_config(bond_id: String) -> Dictionary

# 临时标签（大招/技能用）
func add_temp_tag(tag: String) -> void
func remove_temp_tag(tag: String) -> void

# UI 辅助
func get_bond_status_text(bond_id: String, count: int) -> String
func get_bond_tooltip_text(bond_id: String, current_count: int) -> String
func get_tag_sources(bond_tag: String) -> Dictionary

# 变身过载模式
func set_overdrive_mode(enabled: bool) -> void
```

### 2.6 配置文件: bond_config.csv

路径: `config/player/bond_config.csv`

| 列名 | 说明 | 示例 |
|------|------|------|
| bond_id | 羁绊ID | inkborn |
| type | 类型 | origin / mastery / tactic |
| level | 等级 | 1, 2, 3 |
| required_count | 激活需求数量 | 2, 3, 5 |
| effect_type | 效果类型 | stat_mod / mechanic |
| effect_param | 效果参数 | max_health_pct / super_armor |
| effect_value | 效果数值 | 0.25 / 1 |
| icon_path_index | 图标编号 | 1 |
| display_name | 显示名称 | 魔导 |
| description | 效果描述 | 魔法自然回复速度+30% |

### 2.7 添加新羁绊的步骤

1. 在 `bond_config.csv` 中添加羁绊的各等级行
2. 在 `player_config.csv` 中为角色分配对应标签（origin_tag / mastery_tag / tactic_tag）
3. （可选）在 `emblem_config.csv` 中创建对应徽章
4. （可选）在 `item_config.csv` 中创建对应 Tier 3 圣物
5. 如果效果类型是 `mechanic`，需要在技能代码中添加查询逻辑
6. 重启游戏使配置生效

可使用自动化工具: `tools/create_bond_tool.gd`（在 Godot 编辑器中 File -> Run）

## 三、道具系统 (Item System)

### 3.1 道具分层

| 层级 | 类型 | 说明 | 示例 |
|------|------|------|------|
| Tier 0 | 消耗品 | 立即使用，不占槽位 | 生命药水、能量药水 |
| Tier 1 | 属性道具 | 直接加固定数值 | 生命药水(+50HP)、疾风靴(+50速度) |
| Tier 2 | 魔法道具 | 百分比修正 + 基础属性 | 火焰之心(攻击+15, 火焰伤害+20%) |
| Tier 3 | 圣物道具 | 高属性 + 修正 + 羁绊标签 | 巨擘圣物(HP+500, 生命+15%, colossus标签) |

### 3.2 核心管理器

#### EquipmentManager (`autoloads/equipment_manager.gd`)

管理每个角色的装备槽（每人 1 个道具槽）。

```gdscript
# 装备/使用道具（统一入口）
func equip_or_use_item(player_id: String, item_id: String, slot_index: int = 0) -> bool

# 获取装备信息
func get_equipped_item(player_id: String) -> int
func get_equipped_item_data(player_id: String) -> Dictionary
func is_equipped(player_id: String) -> bool

# 卸下装备
func unequip_item(player_id: String) -> bool
```

#### WarehouseManager (`autoloads/warehouse_manager.gd`)

管理 48 格道具仓库，持久化存储。

```gdscript
# 仓库操作
func add_item(item_type: int) -> bool
func remove_item(slot_index: int) -> bool
func get_item_at_slot(slot_index: int) -> int

# 配置查询
func get_item_config(item_type: int) -> Dictionary
func get_item_config_by_id(item_id: String) -> Dictionary

# ID 转换
func get_item_id_from_type(item_type: int) -> String
func get_type_from_item_id(item_id: String) -> int
```

#### EmblemManager (`autoloads/emblem_manager.gd`)

管理局内持有的徽章和遗物（全局效果，不绑定角色）。

```gdscript
# 添加/移除

func add_wildcard() -> void
func assign_wildcard(emblem_index: int, target_bond_tag: String) -> void
func remove_emblem(index: int) -> void
func clear_all() -> void

# 查询
func get_emblem_tags() -> Dictionary          # {bond_tag: count}
func get_emblems_for_bond(bond_id: String) -> int
func get_all_emblems() -> Array[Dictionary]
func has_unique_relic(emblem_id: String) -> bool

# 序列化（局内存档）
func serialize() -> Dictionary
func deserialize(data: Dictionary) -> void
```

#### 信号

| 管理器 | 信号 | 说明 |
|--------|------|------|
| EmblemManager | `emblem_added(emblem_data)` | 护符添加 |
| EmblemManager | `emblem_removed(emblem_data)` | 护符移除 |
| EmblemManager | `wildcard_assignment_requested(emblem_data)` | 万能鬼牌需要分配 |

### 3.3 配置文件

#### item_config.csv (`config/item/item_config.csv`)

主道具配置，包含所有可装备道具和消耗品。

| 列名 | 说明 | 示例 |
|------|------|------|
| id | 道具ID | relic_colossus |
| name | 显示名称 | 巨擘圣物 |

| type | 类型 | equipment / consumable |
| slot_type | 槽位 | weapon |
| base_stat | 基础属性 | hp / speed / attack |

| mod_type | 修正类型（分号分隔多个） | max_health_pct |
| mod_value | 修正数值（分号分隔多个） | 0.15 |
| bond_grant | 提供的羁绊标签 | colossus |

| icon_path | 图标路径 | res://assets/sprites/Icons/... |

#### emblem_config.csv (`config/item/emblem_config.csv`)

徽章和遗物配置（通过 EmblemManager 管理的全局道具）。

| 列名 | 说明 | 示例 |
|------|------|------|

#### shop_item_config.csv (`config/item/shop_item_config.csv`)

波次间商店的消耗品配置，支持权衡型道具（同一 item_id 多行，正面+负面效果）。

| 列名 | 说明 |
|------|------|
| item_id | 道具ID |
| item_name | 名称 |
| item_type | 类型（consumable） |
| item_tier | 层级 |
| effect_type | 效果类型（flat_add / percent_add） |
| effect_target | 目标（stat / modifier） |
| target_tags | 目标标签 |
| effect_value | 数值（负数为减益） |
| price | 价格 |
| shop_weight | 出现权重 |
| is_trade_off | 是否为权衡效果行（0/1） |

### 3.4 添加新道具的步骤

#### 添加装备道具（Tier 1/2/3）

1. 在 `item_config.csv` 末尾添加一行
2. Tier 3 圣物需要填写 `bond_grant` 列（对应 bond_config.csv 中的 bond_id）
3. 重启游戏，道具会自动出现在 WarehouseManager 的配置中

#### 添加徽章/遗物

1. 在 `emblem_config.csv` 末尾添加一行
2. 徽章的 `bond_tag` 必须与 bond_config.csv 中的 bond_id 匹配
3. 遗物设置 `is_unique=1`，同一局内不可重复持有

#### 添加商店消耗品

1. 在 `shop_item_config.csv` 末尾添加一行（或多行用于权衡型）
2. 权衡型道具：同一 `item_id` 写两行，`is_trade_off=0` 为正面效果，`is_trade_off=1` 为负面效果

可使用自动化工具: `tools/create_item_tool.gd`（在 Godot 编辑器中 File -> Run）

## 四、数据流

### 4.1 战斗初始化流程

```
角色选择完成
    │
    ├── 1. PlayerFactory 创建角色实例
    │       └── PlayerBase._ready() → 加载装备 → 应用 Tier1/Tier2 效果
    │
    ├── 2. BondManager.recalculate_active_bonds(team_ids)
    │       ├── 来源1: 角色自带标签 (origin_tag + mastery_tag + tactic_tag)
    │       ├── 来源2: 装备 bond_grant (EquipmentManager)
    │       ├── 来源3: 全局徽章 (EmblemManager.get_emblem_tags())
    │       └── 来源4: 临时标签 (temp_bonus_tags)
    │
    ├── 3. 激活满足阈值的羁绊
    │       ├── stat_mod → apply_stat_modifiers() → 修改玩家属性
    │       └── mechanic → 注册到 active_bonds，供运行时查询
    │
    └── 4. BondHUD 更新显示
```

### 4.2 运行时查询

```gdscript
# 技能代码中查询 mechanic 效果
if BondManager.has_mechanic("closed_shape_dmg"):
    var bonus = BondManager.get_mechanic_value("closed_shape_dmg")
    damage *= (1.0 + bonus)

# 查询属性加成
var modified_stats = BondManager.apply_stat_modifiers(base_stats)
```

## 五、UI 组件

### 5.1 BondHUD (`scenes/ui/bond_hud/`)

战斗界面左下角的羁绊图标显示。

- `bond_hud.gd` / `bond_hud.tscn`：主容器，分上下两排（激活/未激活）
- `bond_icon.gd` / `bond_icon.tscn`：单个羁绊图标，含等级标签和 Tooltip

自动监听 `BondManager.bonds_recalculated` 信号更新显示。

### 5.2 BondSummaryItem (`scenes/ui/components/`)

选择界面的羁绊统计条目，显示名称、计数、颜色状态。

### 5.3 WildcardPanel (`scenes/ui/wildcard/`)

万能鬼牌分配界面，让玩家选择将鬼牌分配到哪个羁绊标签。

## 七、常用 stat_mod 参数参考

| effect_param | 说明 | 示例值 |
|-------------|------|--------|
| max_health_pct | 最大生命百分比 | 0.25 = +25% |
| energy_regen_pct | 能量回复百分比 | 0.3 = +30% |
| movement_speed_pct | 移动速度百分比 | 0.15 = +15% |
| pickup_range_pct | 拾取范围百分比 | 0.5 = +50% |
| crit_chance | 暴击率（固定值） | 10 = +10% |
| crit_damage | 暴击伤害（固定值） | 0.5 = +50% |
| armor | 护甲（固定值） | 5 |
| dodge_chance | 闪避率 | 0.1 = +10% |
| gold_gain | 金币获取 | 0.1 = +10% |
| exp_gain | 经验获取 | 0.15 = +15% |
