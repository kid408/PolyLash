# QEF自动验收工具_使用说明

更新时间：2026-03-14  
适用实现：`res://scenes/arena/debug_switcher.gd`  
工具入口：`DebugSwitcher`（已在 `project.godot` 中注册为 autoload）

---

## 1. 工具定位

这个工具不是单纯的“快捷切角色”脚本，而是一套战斗内验收辅助能力，主要覆盖下面 4 件事：

1. 用固定热键进入 QEF 测试模式。
2. 在测试模式里录制一段真实键鼠操作。
3. 回放最近一次录制，复现操作过程。
4. 把当前角色的主观评价写入 CSV，方便后续汇总。

如果你只关心 `6 / 7 / 8`：

| 按键 | 当前真实功能 | 前置条件 | 再按一次会怎样 |
|---|---|---|---|
| `6` | 开关测试模式 | 战斗中且有当前激活角色 | 关闭测试模式；若正在录制会先保存；若正在回放会直接停止 |
| `8` | 开关输入录制 | 必须先按 `6` 进入测试模式 | 停止录制并写出 JSON |
| `7` | 回放最近一份录制 | 必须先按 `6` 进入测试模式，且已有录制文件 | 若正在回放，再按一次会停止回放 |

> 重要纠正：当前版本不是 `8` 开测试模式，而是 `6` 开测试模式。  
> `8` 只负责录制，`7` 只负责回放。

## 2. 当前热键总览

主键盘数字和小键盘数字都支持。

| 按键 | 作用 | 备注 |
|---|---|---|
| `6` | 开/关测试模式 | `Ctrl + 6` 不触发 |
| `8` | 开/关录制 | 仅测试模式内生效 |
| `7` | 回放最近录制 | 仅测试模式内生效 |
| `` ` `` | 打开/关闭评价面板 | 可提交当前角色评价 |
| `1 / 2 / 3` | 切到当前分组的第 1 / 2 / 3 个角色 | 仅测试模式内生效 |
| `Tab` | 切到下一组角色 | 每组 3 个角色，循环切换 |

## 3. `6` 键：测试模式总开关

### 3.1 按下 `6` 后会发生什么

按下 `6` 成功进入测试模式后，工具会立刻做这些事：

1. 打开测试模式状态。
2. 开启 `E` 技能无冷却。
3. 开启“角色不受伤害”标记，用于纯手感测试。
4. 把当前场景的波次计时强制改到 `999` 秒，尽量把当前波次停住。
5. 打开左上角运行信息面板，显示当前角色、录制状态、回放状态、角色分组等信息。
6. 根据当前可用角色构建“录制角色池”，按每组 3 个角色分组。
7. 清空当前激活角色的 `E` 技能冷却。
8. 打开 `qef_test_mode_active` 标记，使战斗内自动保存逻辑跳过保存。

可以把它理解成：按下 `6` 后，场景会切到“只做技能验收，不走正常战斗节奏”的状态。

### 3.2 测试模式带来的实际效果

进入测试模式后，代码层面的关键效果如下：

- `E` 技能冷却会被持续清零，刷新频率约为 `0.08` 秒。
- 玩家受到伤害的入口会直接返回，不再扣血。
- 波次计时会被拉长到 `999` 秒。
- 自动保存会被跳过，避免测试数据污染正常进度。
- 角色切换会绕过普通切换冷却，适合连续轮测。

### 3.3 `6` 键不会做什么

`6` 键只负责开关测试模式，不会自动做下面这些事：

- 不会自动开始录制。
- 不会自动开始回放。
- 不会自动导出评价。
- 不会自动帮你切到下一个角色。

所以标准动作是：`6` 进入测试模式，然后按需要再用 `8` 录制、`7` 回放、`` ` `` 提交评价。

### 3.4 再按一次 `6` 会发生什么

如果测试模式已经开启，再按一次 `6` 会执行退出流程：

- 如果当前正在录制，会先保存录制文件，停止原因写成 `key_6_disable`。
- 如果当前正在回放，会立即停止回放。
- 清理测试模式相关标记。
- 清空本轮临时角色池与分组索引。

这意味着：`6` 是整个工具的“总收口键”。

## 4. `8` 键：输入录制开关

### 4.1 使用前提

`8` 键只有在测试模式里才有效。  
如果没先按 `6`，按 `8` 只会提示你先进入测试模式。

### 4.2 第一次按 `8`：开始录制

开始录制时，工具会：

1. 检查当前是否有激活角色。
2. 自动创建目录：`user://qa_reports/input_recordings`
3. 生成录制文件名：`player_ops_YYYYMMDD_HHMMSS.json`
4. 记录录制开始时间、当前角色池、当前队伍快照。
5. 从这一刻开始持续采集输入事件。

### 4.3 录制过程中会记录哪些内容

录制并不只是记一个“按了什么键”，而是同时记录多种信息：

| 事件类型 | 说明 |
|---|---|
| `key` | 原始键盘事件 |
| `mouse_button` | 鼠标按键事件 |
| `mouse_motion` | 鼠标移动事件 |
| `action` | Godot Input Action 事件 |
| `sample` | 每 `0.05` 秒采样一次的状态快照 |
| `switch_group` | 用 `Tab` 切下一组角色 |
| `switch_slot` | 用 `1/2/3` 切当前组槽位 |
| `switch_role` | 实际角色切换信号 |

每一条事件还会附带当前角色信息，例如：

- `player_id`
- `display_name`
- 当前 `E` 技能 ID
- 当前 `E` 技能描述

所以录制文件既能回放输入，也能回溯“这段操作当时是哪个角色在测什么技能”。

### 4.4 `sample` 采样里额外记录了什么

除了原始事件，工具还会每 `0.05` 秒补一帧状态采样，里面包含：

- 当前移动方向
- 鼠标位置
- 玩家位置
- 玩家朝向
- `Q / E / F`
- 左键 / 右键是否按下

这一层采样的意义是：就算老录制文件里没有完整原始事件，回放时仍然可以退化为“按采样状态复现”。

### 4.5 第二次按 `8`：停止并保存

录制中再按一次 `8`，会：

1. 追加 `record_end` 事件。
2. 计算本次录制时长。
3. 把完整 JSON 写到录制目录。
4. 停止录制并刷新状态面板。

这次保存的停止原因会写成：`key_8_stop`。

### 4.6 除了按 `8` 之外，哪些情况也会自动保存录制

当前实现里，录制还会在下面几种情况下自动收尾并保存：

- 退出测试模式时，原因：`key_6_disable`
- 开始回放前，原因：`before_replay`
- 关闭游戏或节点退出时，原因：`game_exit`

这点很重要，因为它说明：

- 你不一定非要手动按第二次 `8` 才能拿到文件。
- 但想让文件边界清晰，最好还是手动按第二次 `8` 收录。

### 4.7 录制文件顶层结构

录制 JSON 顶层主要字段如下：

| 字段 | 含义 |
|---|---|
| `version` | 录制格式版本，当前为 `2` |
| `source` | 录制来源，当前为 `DebugSwitcher` |
| `started_at` | 开始时间 |
| `ended_at` | 结束时间 |
| `duration_sec` | 录制总时长 |
| `stop_reason` | 停止原因 |
| `e_no_cooldown_default` | 录制结束时 `E` 无冷却状态 |
| `initial_squad` | 录制开始时的小队快照 |
| `role_catalog` | 本次涉及角色的静态信息目录 |
| `record_role_pool` | 当时的完整测试角色池 |
| `events` | 时间轴事件列表 |

## 5. `7` 键：最近录制回放

### 5.1 使用前提

要让 `7` 生效，必须同时满足两件事：

1. 已经按 `6` 进入测试模式。
2. `user://qa_reports/input_recordings` 目录下至少有一份录制 JSON。

### 5.2 按下 `7` 后的回放逻辑

按下 `7` 后，工具会按这个顺序执行：

1. 找到目录里文件名最新的一份 `player_ops_*.json`。
2. 如果当前还在录制，会先自动保存本次录制。
3. 读取 JSON。
4. 恢复录制开始时的初始队伍、武器、当前角色索引。
5. 按事件时间轴重新注入输入。
6. 同步处理录制时发生过的角色分组切换、槽位切换和角色切换。

也就是说，`7` 不是“回放当前这局刚刚的按键缓存”，而是“读取磁盘里最新一份录制文件，再完整重放”。

### 5.3 回放时实际会复现什么

回放优先使用录制下来的原始事件：

- 键盘事件
- 鼠标点击
- 鼠标移动
- Input Action 事件

如果某份录制缺少这些原始事件，工具会退化为使用 `sample` 采样状态回放，包括：

- 移动方向
- `Q / E / F`
- 鼠标位置
- 玩家位置修正

### 5.4 再按一次 `7`

如果回放已经在进行中，再按一次 `7` 会请求停止回放。  
工具会释放回放阶段模拟按下的 Action，并把状态切回空闲。

### 5.5 当前回放机制的边界

当前实现有几个使用上要知道的限制：

- 只能回放“最新一份”录制文件，没有内置文件选择 UI。
- 如果录制文件损坏、打不开、格式不对，回放会直接失败。
- 回放只在测试模式中开放，不能脱离测试模式单独使用。

## 6. 测试模式内的角色切换规则

这个工具不是按“固定 3 人队伍”设计的，而是按“完整角色池分组轮测”设计的。

### 6.1 分组方式

- 工具会优先从 `ConfigManager.get_enabled_players()` 构建角色池。
- 如果拿不到启用角色列表，就退回当前 `Global.selected_player_ids`。
- 角色池每 `3` 个角色分成一组。

例如角色池有 8 个角色时，分组会是：

- 第 1 组：角色 1、2、3
- 第 2 组：角色 4、5、6
- 第 3 组：角色 7、8

### 6.2 切换方式

| 按键 | 作用 |
|---|---|
| `1` | 切到当前组第 1 个角色 |
| `2` | 切到当前组第 2 个角色 |
| `3` | 切到当前组第 3 个角色 |
| `Tab` | 切到下一组，循环往后 |

### 6.3 这些切换会不会被录进去

会。  
如果你在录制过程中用 `1 / 2 / 3 / Tab` 切角色，录制文件里会写入：

- `switch_group`
- `switch_slot`
- `switch_role`

因此回放时，角色切换过程也会被尽量复现。

## 7. 评价面板与 CSV 输出

虽然你这次主要问的是 `6 / 7 / 8`，但这份工具说明最好把评价入口一起写清楚，因为它和验收流程是连在一起的。

### 7.1 打开方式

按 `` ` `` 打开或关闭评价面板。

### 7.2 可以记录什么

面板里可以填写或勾选这些内容：

- 预设结论：如“手感顺畅”“需要调优”“偏强”“偏弱”“有BUG”
- 评分：`1` 到 `5`
- 关注维度：伤害、范围、前摇、后摇、打击感、生存、连招流畅度
- 问题标签：卡顿、判定、文本、特效、音效、交互
- 自由备注

### 7.3 提交方式

- `Enter`：提交
- `Esc`：关闭

如果你什么都没勾、备注也没填，工具会拒绝提交。

### 7.4 CSV 文件位置与字段

评价会写到：

`user://qa_reports/character_feedback_YYYYMMDD.csv`

CSV 每行会带上这些信息：

- 时间戳
- `player_id`
- 角色显示名
- `Q` 技能 ID
- `E` 技能 ID
- `Q` 描述
- `E` 描述
- `F` 名称
- 预设结论
- 评分
- 关注维度
- 问题标签
- 自由备注
- 当前录制文件路径
- 最近一次回放文件路径

这意味着你在录完、回放完之后再填评价，CSV 可以直接关联到对应的录制文件。

## 8. 输出文件位置

当前工具会写两类文件：

| 类型 | 路径 |
|---|---|
| 录制 JSON | `user://qa_reports/input_recordings/player_ops_YYYYMMDD_HHMMSS.json` |
| 评价 CSV | `user://qa_reports/character_feedback_YYYYMMDD.csv` |

`user://` 是 Godot 的用户数据目录。  
在 Windows 的编辑器/调试运行环境下，通常会落在：

`%APPDATA%\\Godot\\app_userdata\\PolyLash\\qa_reports\\...`

实际绝对路径以运行日志里打印出来的路径为准，因为工具在开始录制、保存录制、开始回放、提交评价时都会输出实际路径。

## 9. 推荐验收流程

如果你要做一轮比较标准的 QEF 自动验收，推荐按这个顺序：

1. 进入战斗场景。
2. 按 `6` 进入测试模式。
3. 用 `Tab`、`1 / 2 / 3` 切到目标角色。
4. 按 `8` 开始录制。
5. 执行你要验收的 `Q / E / F` 操作。
6. 按 `8` 停止录制。
7. 按 `7` 回放刚才那份最新录制，检查是否能复现。
8. 按 `` ` `` 打开评价面板，填写结论和备注。
9. 切到下一个角色，重复上面的流程。
10. 全部测完后，再按一次 `6` 退出测试模式。

如果你这轮只想快速试手感，不需要留痕，也可以只做：

`6 -> 测技能 -> 打开评价面板（反引号键） -> 记评价 -> 6`

## 10. 常见问题

### 10.1 为什么按 `8` 没反应

最常见原因是还没按 `6` 进入测试模式。

### 10.2 为什么按 `7` 没反应

通常有两个原因：

- 还没进入测试模式
- 录制目录下还没有任何 `player_ops_*.json`

### 10.3 为什么测试过程中没有自动保存

这是故意的。  
测试模式会打开 `qef_test_mode_active`，战斗内自动保存逻辑会直接跳过保存，避免测试把正式进度覆盖掉。

### 10.4 为什么旧文档写的是 `8` 开测试模式

因为那是旧版本说明。  
当前仓库实现已经变成：

- `6`：测试模式
- `8`：录制
- `7`：回放

这份文档应以当前代码实现为准。

### 10.5 角色不止 3 个时怎么测

用 `Tab` 切组，用 `1 / 2 / 3` 切组内角色。  
工具本来就是按“3 个一组轮测全部角色”设计的。
