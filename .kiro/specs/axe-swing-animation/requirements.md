# 斧头挥舞动画需求文档

## 1. 概述

**功能名称**: 斧头挥舞动画修复  
**优先级**: 高  
**状态**: 待实现

## 2. 背景

### 当前问题
用户反馈："近战武器的斧子，没有挥舞的效果"

### 现状分析
- ✅ 碰撞检测正常（扇形范围）
- ✅ 伤害计算正常
- ❌ 视觉动画不明显：斧子没有明显的"挥舞"感觉
- ❌ 用户期望：能看到斧子从上往下挥砍的弧形轨迹

### 用户期望
用户想要看到明显的"挥舞"动画效果：
- 斧子从后上方举起
- 沿着弧形轨迹向前下方挥砍
- 有明显的位置移动和旋转变化
- 动画流畅自然

## 3. 需求分析

### 3.1 功能需求

#### FR-1: 扇形武器挥砍动画
**描述**: 为扇形武器（axe, mace等）实现明显的挥砍动画

**验收标准**:
- 武器从后上方举起（起始位置）
- 沿弧形轨迹向前下方挥砍（攻击阶段）
- 旋转角度变化明显（-60° → +60°）
- 位置偏移明显可见
- 动画流畅，无卡顿

#### FR-2: 动画时序优化
**描述**: 优化动画执行时序，确保挥砍动画可见

**验收标准**:
- 跳过传统的后坐力阶段（对于扇形武器）
- 直接从举起位置开始
- 挥砍动画在Hitbox启用时执行
- 收回阶段位置和旋转并行恢复

#### FR-3: 参数可调整性
**描述**: 动画参数可通过CSV配置调整

**验收标准**:
- 攻击时长可调整（attack_duration）
- 收回时长可调整（back_duration）
- 攻击范围影响挥砍幅度（max_range）
- 扇形角度可配置（sector_angle）

### 3.2 非功能需求

#### NFR-1: 性能
- 动画不影响游戏帧率
- Tween动画高效执行

#### NFR-2: 兼容性
- 不影响其他武器类型的动画
- 保持现有碰撞检测逻辑

#### NFR-3: 可维护性
- 代码清晰易懂
- 动画逻辑集中管理

## 4. 技术约束

### 4.1 现有系统
- 使用Godot Tween系统
- 武器配置存储在CSV文件中
- 近战行为由`MeleeBehavior`类管理

### 4.2 限制条件
- 必须保持现有的碰撞检测逻辑
- 不能破坏其他武器类型的动画
- 动画时长必须与CSV配置一致

## 6. 验收标准

### 6.1 功能验收
- [ ] 斧头有明显的从上往下挥砍动画
- [ ] 旋转角度变化可见（-120° → +120°，总计240°）
- [ ] 位置偏移可见（弧形轨迹，横向260px，纵向220px）
- [ ] 动画流畅，无卡顿
- [ ] 碰撞检测正常工作
- [ ] **关键**: Hitbox在整个挥砍动画期间保持启用（0.3秒）
- [ ] **关键**: 伤害在挥砍过程中造成，不是动画结束后
- [ ] **关键**: 日志显示正确的时序（启用→等待0.3秒→禁用）

### 6.2 性能验收
- [ ] 动画不影响游戏帧率
- [ ] 无内存泄漏
- [ ] Tween正确清理

### 6.3 兼容性验收
- [ ] 其他近战武器动画正常
- [ ] 远程武器不受影响
- [ ] 现有功能不受破坏

### 6.4 时序验收 ⚠️ **新增**
- [ ] 控制台日志显示：
  ```
  [MeleeBehavior] Hitbox 启用 - 挥砍开始
  [等待 0.3 秒...]
  [MeleeBehavior] Hitbox 禁用 - 挥砍动画结束
  ```
- [ ] 不应该看到立即禁用的日志
- [ ] 挥砍轨迹上的敌人能被击中
- [ ] 伤害时机与动画同步
