# 全角色技能设计基础标准

## 1. 文档目的

- 本标准用于约束全角色的技能玩法设计、角色差异性设计、协同设计与玩法验收。
- 本标准回答的是“角色技能应该怎么设计才对”，不是“系统如何实现”。
- 角色设计时必须同时满足两层要求：`玩法成立` 与 `系统口径成立`。
- 角色技能方案必须优先服务三个目标：`主玩法清晰`、`角色玩法唯一`、`切人协同成立`。

## 2. 基础认知

- 开局只上场 `1` 名角色，局内招募或替换到最多 `3` 人。
- 敌人追玩家，`Q 画线` 是主玩法本体。
- `Q 非闭合` 承担日常输出、保命、走位、拉怪与做局。
- `Q 闭合` 负责高价值收口和大面积爽点。
- `E` 是二次介入，不抢 `Q` 的主玩法位置。
- `F` 是终极技能，不承担日常循环职责。
- `F` 在技能设计层的定位是：`用于集中兑现前面做出的局的高价值终极手段`。
- 左键 `dash` 是全角色共享的通用保命位移，不是角色主玩法本体。

## 3. 角色设计必须同时遵守的系统尺子

本节不是要求你在角色文档里展开系统设计，而是提醒你：角色方案必须能落进已经拍板的系统边界内。

### 3.1 统一行动经济口径

- `Q` 成本正式定义为：`线长成本 + 闭合税`。
- `E` 正式采用：`固定成本 + 固定冷却`。
- `dash` 只保留：`低占用、保命优先、轻联动` 的定位。
- 常规经济统一采用：`日常模板 / 高压模板 / 高光模板` 三套预算。
- `Q` 规划态慢时是正式系统特性，角色设计不得破坏其判断价值。

### 3.2 统一测量单位

- 当前项目统一采用：`1U = 600`。
- `Q短线 = 300 = 0.5U`
- `Q中线 = 600 = 1.0U`
- `Q长线 = 900 = 1.5U`
- `超长线 = 1800+ = 3U+`

这套长度分类是预算尺，不是强制限制玩家画线长度。

### 3.3 常规成本基准

- `Q短线成本 = 0.5U`
- `Q中线成本 = 1.0U`
- `Q长线成本 = 1.5U`
- `Q闭合税 = 0.8U`
- `E基准成本 = 1.5U + 固定冷却`
- `dash基准成本 = 0.25U + 短冷却`

角色设计不要求把数值写成 `U`，但你的方案必须能被换算回这套公共尺子。

### 3.4 三套预算模板

#### 日常模板

- `4 次 Q中线非闭合`
- `1 次 Q中线闭合`
- `2 次 E`
- `1 次 dash`
- 预算基准：`B_day = 9.05U`

#### 高压模板

- `2 次 Q短线非闭合`
- `1 次 E`
- `2 次 dash`
- 预算基准：`B_press = 3.0U`

#### 高光模板

- `2 次 Q短线非闭合`
- `1 次 Q中线闭合`
- `1 次 E`
- `1 次 dash`
- 预算基准：`B_glow = 4.55U`

角色技能方案必须回答：

- 这个角色的日常循环是否能自然落进 `日常模板`。
- 这个角色在危险时是否还能保有 `高压模板` 的求生权。
- 这个角色开 `F` 后是否真的有能力把 `高光模板` 打完整。

### 3.5 资源原型边界

常规角色只允许落在以下三种资源原型中：

- `标准型`
- `高储能型`
- `高回能型`

边界如下：

- 资源原型只改节奏形状，不改总强度。
- 所有常规角色的 `30 秒总预算` 不应明显膨胀。
- 不允许同一角色同时显著 `高储能` 又显著 `高回能`。
- 如果角色需要更肥的资源节奏，必须同步付出代价，比如 `E 更贵`、`Q 超长惩罚更重`、`移动更弱`、`闭合税更高`。

### 3.6 E 偏置角色边界

`E 偏置角色` 可以存在，但必须遵守：

- `Q 相关预算 / 日常预算 >= 50%`
- `E 相关预算 / 日常预算 <= 33%`
- `E 偏置角色` 上限可放宽到 `<= 38%`
- `dash 相关预算 / 日常预算 <= 8%`

结构要求如下：

- `E` 的高价值必须优先来自“改写 Q 已经做好的场”。
- 不允许 `E` 脱离 `Q` 独立完成整套主循环。
- 不允许 `E` 同时承担主要输出、主要控制、主要收口三件事。

`E 偏置角色` 只允许把以下一项做成主优势：

- `E 更便宜`
- `E 冷却更短`
- `E 命中后返还少量常规预算`

最多再附带一项弱副优势，不允许三项同时强。

### 3.7 dash 边界

- `dash` 不参与主循环预算争夺。
- `dash` 不承担主要输出职责。
- `dash` 不承担主要收口职责。
- 角色可以和 `dash` 联动，但联动价值不得反客为主。

允许的 `dash` 联动方向：

- 补位
- 穿越自己布好的 `Q` 场
- 触发轻量标记、击退、回位、引爆

不允许的方向：

- 把 `dash` 做成比 `Q` 更重要的输出主键
- 把 `dash` 做成 `F` 窗口的主要收益按钮

### 3.8 F 窗口边界

- `F` 是独立终极资源，不进入常规经济公式。
- `F` 的系统减负目标，是让玩家在 `35% - 40%` 常规能量入场时，仍然能完成一轮高光收口。
- `F` 窗口需要补足的常规预算缺口，公共目标约为 `0.8U - 1.1U`。
- `F` 的减负优先级固定为：`Q闭合税 > Q线长成本 > E条件返还`。
- `dash` 不参与系统级减负。

这意味着角色设计时，`F` 的爽感重点必须是：

- 让玩家从“继续拖怪”切换成“冲回自己做好的场里收”

而不是：

- 单纯加数值
- 单纯给无敌
- 单纯发一个和前面做局无关的大招

## 4. 第一原则：每个角色的玩法必须唯一

- 每个角色都必须拥有不可替代的玩法签名，不能只是同一套结构换皮。
- 角色差异必须优先于数值差异，先区分玩法，再谈强弱和平衡。
- 玩家在一段短实战中，不看角色名，也能说出“这个角色怎么做局、怎么收口、怎么高光”。
- 每个角色都必须同时拥有唯一的 `主循环`、唯一的 `高光兑现方式`、唯一的 `对外协同价值`。
- 只更换元素、颜色、伤害类型、状态名字、范围大小、倍率高低，不算玩法差异。
- 只把“压一坨怪”“铺一片持续区”“点低血目标”“开大打一轮”换个包装，不算角色特色。
- 如果两个角色在核心循环和高光兑现上只是近义重复，则视为同构，必须重做。

## 5. 每个角色必须回答的四个问题

- `Q 开线` 到底如何改写追击关系。
- `Q 闭合` 到底把什么收成什么。
- `E` 的第二道命令到底改了什么。
- `F` 到底在什么时机开、对什么目标开、如何把收益兑现出来。

如果一个角色与另一个角色的大部分答案高度相似，就说明特色不足。

## 6. Q / E / F 的统一职责

### 6.1 Q 非闭合

- `Q 非闭合` 必须是角色最稳定、最常用、最能体现个性的主循环。
- 玩家不开 `F`、不依赖 `Q 闭合`，也必须能靠 `Q 非闭合 + 走位 + dash` 正常游玩。
- `Q 非闭合` 必须改变追击关系，而不只是多一段伤害。
- `Q 非闭合` 必须留下可继续经营的战场资产。
- 这个资产既要能被自己继续利用，也要能被后手角色接住。

### 6.2 Q 闭合

- `Q 闭合` 必须建立在已有开放资产之上。
- `Q 闭合` 的本质是“收局”，不是另起一个无关的新技能。
- `Q 闭合` 必须明显高于 `Q 非闭合` 的日常价值，承担高价值收口和大面积爽点。
- `Q 闭合` 应该值得等待、值得判断时机、值得赌位置。
- 任何角色都不能因为没打出 `Q 闭合` 就变成残废版。

### 6.3 E

- `E` 是二次介入技能，不是主建场技能。
- `E` 单按必须保底，至少能完成一次明确脱困、拆贴脸、拉口子、短换位或目标修正。
- `E` 接在 `Q` 之后时，必须像“第二道命令”，而不是简单补伤害。
- `E` 可以很强，但不能成为角色最主要的建场来源。
- 玩家大部分日常操作决策，仍应围绕 `Q` 展开。

### 6.4 F

- `F` 是终极技能，不承担日常循环职责。
- `F` 的设计目的不是补平时强度，而是在高价值时机集中兑现前面积累的优势。
- `F` 的高光来源不应只是数值爆发，而应来自主导权提升、收益兑现和角色签名行为的放大。
- `F` 的统一体验要求不是字面意义上的“追怪”，而是让玩家从“保守拖怪”转入“主动收账”。
- 每个角色的 `F` 都必须写清三件事：`最佳启动时机`、`主要收益对象`、`收益兑现方式`。
- `F` 必须足以支撑“值得消耗一次共享终极资源”的身份。
- `F` 不应长期稳定压倒其他角色的 `F`，避免共享终极资源退化为单角色垄断。

## 7. 角色协同标准

- 每个角色都必须回答：`我能为别人留下什么价值`
- 每个角色都必须回答：`我最擅长接住别人留下的什么价值`
- 协同只写“价值接力”，不写“固定绑定角色组合”。
- 每个角色至少要稳定提供以下三类价值中的 `2` 类：`空间价值`、`目标价值`、`资产价值`

说明如下：

- `空间价值` 指区域、路径、窄口、危险侧、安全侧、据点、通道、压缩区等可被后手角色继续利用的场面。
- `目标价值` 指低血目标、名单目标、被压缩目标、挂状态目标、露背目标、高价值精英等可被后手角色优先处理的对象。
- `资产价值` 指炮位、虫巢、节点、站点、补给物、引爆点、召唤物等可被后手角色继续借用的资产。

协同必须是开放式的：

- 同一份价值应允许多个角色接住，而不是只服务一个固定搭档。
- 角色不能只提供“自己爽”的收益，而不给后手角色留下可见、可接、可兑现的战场价值。

## 8. dash 的技能设计定位

- 左键 `dash` 是全角色共享的通用保命位移动作。
- `dash` 的主要用途是逃生、躲避、穿位、过险位与高风险操作。
- 角色可以围绕 `dash` 设计联动收益。
- `dash` 联动属于角色增益层，不应成为角色成立的唯一前提。
- 角色差异不得建立在改写通用 `dash` 的基础定位上。

## 9. 全局 Combo 设计标准

- `Combo` 是全角色共用的高操作认证规则，不绑定某个角色。
- `Combo` 不允许设计成固定按键串或固定输入顺序。
- `Combo` 必须和高风险操作、场面经营、时机兑现有关。
- `Combo` 的基础认证采用 `8s` 三印规则：`险印`、`局印`、`收印`

说明如下：

- `险印` 表示玩家在危险局面中完成一次高质量脱困、穿阵、切侧或反切。
- `局印` 表示玩家成功把怪从“正在追你”改成“可处理态”。
- `收印` 表示玩家在已经做好的坏位置上打出一次高价值兑现。

补充要求：

- `F` 可以帮助玩家创造高光，但不能直接白送完整 `Combo`。
- `Combo` 的目标不是奖励背输入法，而是奖励高压下的判断、做局和收局能力。

## 10. 统一禁止项

- 禁止同构换皮。
- 禁止只靠元素和数值变化伪装角色差异。
- 禁止 `E` 抢走 `Q` 的主玩法位置。
- 禁止 `Q 闭合` 变成与 `Q 开线` 无关的独立大招。
- 禁止 `F` 退化成纯增伤、纯无敌、纯清屏或纯爆发按钮。
- 禁止把 `F` 设计成平时不用、只看倍率的空心技能。
- 禁止让角色变成“不闭合就玩不动”或“不开发力窗口就没有体验”。
- 禁止把角色差异建立在改写通用 `dash` 定位上。
- 禁止把协同写成强制固定配队。
- 禁止角色只吃自己留下的收益，完全无法服务后手角色。
- 禁止用更高数值掩盖玩法空心和角色同构。

## 11. 最低验收标准

- 玩家不开 `F` 时，能稳定完成日常循环。
- 玩家单按 `E` 时，能明显感受到保底脱困或场面修正。
- 玩家使用 `Q 非闭合` 时，能明显看出自己在做局。
- 玩家打出 `Q -> E` 时，能明显看出 `E` 是第二道命令。
- 玩家打出 `Q 闭合` 时，能明显看出这是对前面场面的高价值收口。
- 玩家开启 `F` 时，能明显感受到自己开始主动兑现前面做出的局。
- 玩家切人后，下一角色能看懂上一角色留下的价值，并且接得上。
- 玩家观察 `20 秒` 实战片段时，能说出该角色的玩法签名，而不是把它当成其他角色的变体。
- 去掉元素名和数值描述后，该角色仍能靠行为逻辑被识别出来。
- 如果测试者能用另一个现有角色的描述完整替代该角色，则判定为特色不足。

## 12. 角色设计写作模板

每个角色技能文档都必须至少回答以下内容：

- 一句话角色幻想
- 角色的玩法签名
- `Q 非闭合` 的日常循环是什么
- `Q 开线` 如何改写追击关系
- `Q 闭合` 把什么收成什么
- `E 单按` 如何保底
- `E 接 Q` 的第二道命令是什么
- `F` 的最佳启动时机是什么
- `F` 的主要收益对象是什么
- `F` 的收益兑现方式是什么
- 我能为别人留下什么价值
- 我最擅长接住什么价值
- 我的 `dash` 联动高操作点是什么
- 我的自然 `Combo` 路线是什么
- 我与最相近角色的核心差异是什么

## 13. 角色设计的系统自检

在角色文档进入具体数值前，必须先做一轮系统自检：

- 这个角色的常规循环更接近 `标准型`、`高储能型` 还是 `高回能型`
- 这个角色是否需要 `E 偏置`，如果需要，主优势是哪一种
- 这个角色的 `Q` 主循环是否能自然落进 `日常模板`
- 这个角色在低能量状态下是否还能保住 `高压模板`
- 这个角色的 `F` 是否真的在帮助玩家完成 `高光模板`
- 这个角色的 `F` 减负是否优先服务于 `Q闭合税` 和 `Q线长成本`
- 这个角色的 `dash` 联动是否已经越过“轻联动”边界

如果一个角色在这 7 项里有 2 项以上答不上来，说明它还不适合进入技能细化阶段。

## 14. 设计判断原则

- 先判断这个角色“怎么做局”，再判断它“怎么收局”，最后判断它“能给别人留下什么”。
- 如果一个角色的描述离开数值就站不住，说明玩法还没设计出来。
- 如果一个角色的爽点只能靠 `F` 才成立，说明日常循环有问题。
- 如果一个角色只会自己闭环，不会给队友留值，说明协同设计不成立。
- 如果一个角色可以被另一个角色的描述近乎完整替换，说明差异性不成立。
- 如果一个角色在技能层看起来很帅，但放回系统尺子里明显超预算或越位，优先回调概念，而不是硬补特权。
