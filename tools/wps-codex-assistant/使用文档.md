# WPS Codex 个人助手使用文档

## 1. 这套工具是做什么的

这是一套面向你个人使用的本地代理服务，让你可以把 `WPS 协作` 的消息入口接到一个受限目录内的 `Codex/OpenAI` 助手上。

它的设计目标是：

- 只服务你一个人
- 只访问你预设的白名单目录
- 只执行受控文件任务
- 高风险动作先确认
- 先本地跑通，再对接 WPS

当前版本已经具备：

- 本地服务启动与健康检查
- 本地 `/chat` 联调接口
- WPS `/wps/callback` 占位接口
- 白名单目录访问限制
- 写入、追加、移动、重命名的二次确认

## 3. 使用前准备

### 3.1 环境要求

- Windows PowerShell
- Node.js 20 及以上
- 一个可用的 OpenAI API Key

### 3.2 初始化配置

进入目录：

```powershell
Set-Location D:\wanglei\PolyLash\tools\wps-codex-assistant
```

执行初始化：

```powershell
.\assistant-manager.ps1 -Action init
```

如果当前目录里还没有 `.env`，脚本会自动根据 `.env.example` 生成一份。

### 3.3 修改 `.env`

至少需要配置这些字段：

```env
OPENAI_API_KEY=你的OpenAIKey
WORKSPACE_ROOTS=docs=D:\wanglei\PolyLash\docs
ALLOWED_USERS=
WPS_REPLY_MODE=none
```

说明：

- `OPENAI_API_KEY`：必须填写
- `WORKSPACE_ROOTS`：你允许助手访问的白名单目录
- `ALLOWED_USERS`：本地测试阶段可以先留空
- `WPS_REPLY_MODE=none`：本地联调阶段先不要回推到 WPS

如果你要放多个目录，可以这样写：

```env
WORKSPACE_ROOTS=docs=D:\wanglei\PolyLash\docs;notes=D:\Personal\Notes
```

## 4. 自动化脚本怎么用

脚本文件：

- [assistant-manager.ps1](D:\wanglei\PolyLash\tools\wps-codex-assistant\assistant-manager.ps1)

帮助：

```powershell
.\assistant-manager.ps1
```

支持的动作：

- `init`：初始化 `.env`
- `start`：后台启动服务
- `stop`：停止后台服务
- `restart`：重启服务
- `status`：查看运行状态
- `health`：请求健康检查接口
- `chat`：调用本地 `/chat`
- `callback-demo`：模拟一次 WPS webhook 请求
- `demo`：自动执行一套本地联调流程

## 5. 推荐测试流程

### 5.1 第一步：启动服务

```powershell
.\assistant-manager.ps1 -Action start
```

正常情况下，脚本会：

- 检查 Node.js
- 检查 `.env`
- 在后台启动 `node src/server.js`
- 写入进程 PID 文件
- 尝试请求 `/health`

### 5.2 第二步：查看状态

```powershell
.\assistant-manager.ps1 -Action status
```

### 5.3 第三步：健康检查

```powershell
.\assistant-manager.ps1 -Action health
```

### 5.4 第四步：测试聊天接口

```powershell
.\assistant-manager.ps1 -Action chat -Text "列出可用目录"
```

再测一个更贴近日常使用的例子：

```powershell
.\assistant-manager.ps1 -Action chat -Text "列出 docs 根目录下的文件"
```

### 5.5 第五步：测试确认机制

先发一个写入请求：

```powershell
.\assistant-manager.ps1 -Action chat -Text "在 docs 目录下创建 test.md，内容是 这是一次测试"
```

正常情况下，返回内容会提示你：

- 准备写入哪个文件
- 回复“确认”执行
- 回复“取消”放弃

然后确认执行：

```powershell
.\assistant-manager.ps1 -Action chat -Text "确认"
```

或者取消：

```powershell
.\assistant-manager.ps1 -Action chat -Text "取消"
```

### 5.6 第六步：模拟 WPS 回调

```powershell
.\assistant-manager.ps1 -Action callback-demo -Text "列出可用目录"
```

这一步不是连真实 WPS，而是模拟一条会发到 `/wps/callback` 的消息。

如果这一条也正常，说明服务主链已经跑通，剩下就是把 WPS 真正的事件字段对齐。

## 7. 日常使用建议

推荐你把日常使用分成两类：

### 7.1 本地联调

适合在正式接 WPS 前验证：

- 目录是否配对了
- API Key 是否正确
- 模型是否能调通
- 文件操作是否符合预期

常用命令：

```powershell
.\assistant-manager.ps1 -Action start
.\assistant-manager.ps1 -Action chat -Text "列出 docs 根目录下的文件"
.\assistant-manager.ps1 -Action stop
```

### 7.2 接入 WPS 后

接入后，WPS 会作为消息入口，而本地服务负责：

- 识别消息内容
- 调用 Codex/OpenAI
- 在白名单目录里执行受控动作
- 返回结果

## 8. WPS 对接前你还需要准备什么

当本地联调通过以后，还需要补 3 样东西：

- 你的 WPS webhook 配置地址
- WPS 实际发来的事件 JSON
- WPS 回消息方式

## 9. 常见问题

### 9.1 启动失败

先看：

```powershell
.\assistant-manager.ps1 -Action status
```

如果需要看日志，脚本会把运行日志放到：

- `data\run\assistant.out.log`
- `data\run\assistant.err.log`

### 9.2 `/health` 正常，但 `/chat` 失败

优先检查：

- `.env` 是否有 `OPENAI_API_KEY`
- Key 是否可用
- `WORKSPACE_ROOTS` 是否是绝对路径

### 9.3 文件读写失败

优先检查：

- 访问的路径是否在白名单目录内
- 路径是不是相对白名单目录
- 目标是不是文本文件

### 9.4 为什么助手不能随便访问整个磁盘

这是故意设计的安全边界。当前版本只允许访问你显式配置到 `WORKSPACE_ROOTS` 的目录。
