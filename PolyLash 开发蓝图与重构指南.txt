PolyLash 开发蓝图与重构指南 (v1.0)
版本日期: 2026-02-23
项目阶段: 核心玩法打磨 -> 局内成长系统构建 (Alpha Refactoring)
1. 项目核心画像 (Project Context)
1.1 基础玩法
类型: 动作 Roguelike / 幸存者 Like (Survivor-like)
核心机制: 画线施法 (Draw-to-Cast)。Q技能进入子弹时间，鼠标画线/圈地生成技能效果（墙体、陷阱、爆炸区）。
角色系统: 共 32 个角色，玩家选 3 人组成小队进入游戏。
战斗方式:
自动攻击: 角色自带武器自动射击（类似土豆兄弟）。
手动技能: Q（画线消耗能量）、E（瞬发小技能）、F（大招/变身）。
切换机制: 战斗中按 1/2/3 键切换当前操控角色。
1.2 当前进度与痛点
已完成: 32个角色的基础技能实现、画线物理检测、基础商店（金币购买）、基础UI。
缺失/问题:
缺乏局内成长: 目前只有金币商店，没有XP/升级/三选一构建，导致战斗缺乏长期驱动力。
战斗割裂: 自动攻击和Q技能各打各的，缺乏交互。
体验平淡: 只有数值堆砌，缺乏Roguelike的“质变”爽感。
平衡担忧: 担心无限时间的召唤物导致视觉污染和性能问题。
2. 核心设计哲学修正 (Design Philosophy)
2.1 Roguelike 的定义修正
游戏的乐趣公式 = (战斗机制 + 局内成长) × 构建策略。
行动: 停止单纯打磨“战斗手感”，立即引入“局内成长循环”（XP -> 升级 -> 获得Tag/道具）。
2.2 普攻与技能的关系
旧思路: 普攻打伤害，技能打大伤害。
新思路:
Q技能 (The Nuke): 核心输出与控场手段。
普攻 (The Utility): 功能性工具。负责回蓝（充能）、推怪（聚怪）、挂Debuff（标记）。
2.3 羁绊系统的作用
羁绊不应只提供数值（如伤害+10%），而应提供机制改变（如墙体反伤、爆炸连锁）。
3. 系统架构详解 (System Architecture)
3.1 羁绊分类体系 (11种)
为了平衡随机池深度与构建难度，采用 4+4+3 结构。
A. 起源羁绊 (Origin) - 定义基础属性
重装 (Colossus): 生命上限 / 霸体 / 减伤。
魔导 (Inkborn): 能量回复 / 技能循环 / 击杀回蓝。
游侠 (Nomad): 移动速度 / 闪避 / 移速转攻。
后勤 (Alchemist): 金币获取 / 拾取范围 / 商店折扣。
B. 精通羁绊 (Mastery) - 决定Q技能形态 (重点重构)
通过标签系统 (Tag System) 实现通用逻辑，无需为32个角色单独写代码。
爆破 (Blaster) -> 对应 Tag: [Zone], [Trap]
效果: 闭合区域爆炸、陷阱可手动引爆、连锁反应。
筑墙 (Architect) -> 对应 Tag: [Wall], [Obstacle]
效果: 墙体反伤、拥有生命值（而非时间限制）、碰撞挤压。
咒术 (Hexer) -> 对应 Tag: [Debuff], [DoT]
效果: 状态传染、画线残留毒素、斩杀低血量。
几何 (Geometrist) -> 对应 Tag: [Projectile], [Shape]
效果: 完美图形暴击、多边形特效、投射物弹射。
C. 战术羁绊 (Tactic) - 决定切换风格
突击 (Vanguard): 鼓励高频切换。
Lv.1: 切换冷却 -50%。
Lv.3: 切换时释放“登场技”（如周围震开）。
指挥 (Commander): 鼓励单核站场。
Lv.1: 后台角色 30% 属性加给前台。
Lv.3: 后台角色以幽灵形态出现协助攻击。
支援 (Assist): 鼓励技能流。
Lv.1: 后台技能冷却加速。
Lv.3: 前台画线闭合时，后台角色自动发射援护飞弹。

为了解决“针对每个技能修改太麻烦”的问题，在 skill_config.csv 中增加 tags 字段。

3.3 解决“无限时长”问题
机制: 最大存在数量 (Max Count)。
规则: 每个技能设定 max_count。当生成第 (N+1) 个时，第 1 个自动销毁（或触发销毁特效）。
优势: 防止屏幕混乱，增加策略性（新墙换旧墙），无需担心后期性能。
1. 详细工作规划 (Roadmap)
第一阶段：最小闭环构建 (The Loop)
目标: 让游戏“能玩”，有成长反馈。
经验系统: 实现 怪物掉落XP球 -> 经验条增长 -> 升级事件。
升级UI: 实现简单的“三选一”界面。
道具化羁绊:
创建基础道具数据（如：“火药桶”= +1 Blaster层数）。
在升级选项或商店中刷出这些道具。
验证: 跑通 10 波游戏，确认“捡道具 -> 凑羁绊 -> 变强”的流程成立。
第二阶段：战斗交互重构 (Interaction Refactor)
目标: 让普攻有用，让Q技能有标签。
普攻重做:
近战武器：增加 EnergyRestoreOnHit (命中回蓝 2 点)。
远程武器：增加 Knockback (微弱击退) 或 Mark (标记)。
数据录入: 完善 32 个角色的 skill_config.csv，打好 Zone, Wall, Trap 等标签。
Max Count 机制: 修改 SkillManager，引入对象池或队列管理，限制同类技能场上数量。
第三阶段：羁绊机制实装 (Synergy Implementation)
目标: 实现 Lv.3 的质变效果。
精通羁绊: 编写通用的 Tag 检测逻辑（如上文代码示例），实现 Blaster 和 Architect 的特殊效果。
战术羁绊:
实现 Vanguard 的切换减CD和登场特效。
实现 Commander 的属性共享逻辑。
第四阶段：平衡与打磨 (Polish)
移除跳关: 优化前 5 波的刷怪节奏（增加精英怪），取消“跳过前5波”的功能。
视觉反馈: 为普攻命中、羁绊触发添加明显的视觉/音效反馈。
2. 常见问题备忘 (FAQ)
Q: 普通攻击伤害太低怎么办？
A: 不用加伤害。给它加功能（回蓝、推怪）。它是技能的燃料。
Q: 永久牢笼会卡住怪吗？
A: 不要真的做“永久”。给墙加血条，或者让它能被怪慢慢推开。如果玩家把自己关里面，外面的金币捡不到就是惩罚。
Q: 商店随机性太小？
A: 增加道具池深度。除了羁绊道具，加入“事件道具”（如：下一波怪物全变成史莱姆）。
